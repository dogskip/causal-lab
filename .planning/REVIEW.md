# 3심 설계 검토

## 판정 범위

개발팀용 CRDT·동기화 검증이라는 사용자의 목적 선택을 기준으로 조사와 설계를 검토한다. 설계 수락과 제품 합격은 별개다. 모든 지적은 당시 파일 해시·반례·수정·재검토 결과로 추적한다. 정본은 [PROJECT.md](PROJECT.md)와 [DESIGN.md](DESIGN.md), 공식 근거는 [RESEARCH.md](RESEARCH.md)다.

1·2심의 수정 후 확인과 독립 3심에서 설계 구현 착수를 수락했다. 열린 중요 지적은 세 단계 모두 0건이다. 각 단계의 finalReviewedInputs와 최종 manifest.json으로 실제 파일 해시를 대조한다. 문서의 approved는 설계 검토의 수락 상태다. 제품 조건 G0–G5와 productAcceptance는 미완료/false다.

## 검토 단계

| 단계 | 담당 | 판단 범위 | 근거 |
| --- | --- | --- | --- |
| 1심 | primary_research | 목적 적합성, 대안, 공식 자료의 전달·초기화 전제, 연결 계약 | [review-1.json](evidence/2026-10-14/review-1.json) |
| 2심 | counterexample_review | 반례, 사건 순서, 실패 재생, 불변 자료, SQL 우회, 기한과 호환성 | [review-2.json](evidence/2026-10-14/review-2.json) |
| 3심 | final_design_review | 수정본·해시·실행 결과·요구 추적·단순성의 최종 독립 검토 | [review-3.json](evidence/2026-10-14/review-3.json) |

세 검토는 설계 작성 담당과 구분한다. 같은 지적이 여러 단계에서 발견되면 중복 결함 수로 계산하지 않는다. 독립 재실행과 설계 문구의 확인도 구분한다.

## 실행 증거와 한계

- [Yjs 결과](evidence/2026-10-14/yjs-results.json): 실제 Yjs 13.6.27의 작은 설계 실험이다. 네 복제본의 한정한 입력과 전달·복구를 확인했으며 범용 연결 API를 실행한 결과가 아니다.
- [SQLite 결과](evidence/2026-10-14/sqlite-results.json): SQLite 3.53.1에서 제안 SQL의 제약과 보관을 확인했다. 표본 ID는 합성 값이며 저장기의 JCS·암호 해시·실행 판정을 입증하지 않는다.
- [타입 검사](evidence/2026-10-14/adapter-typecheck.json): TypeScript 5.9.3 strict 검사다. 실제 설치한 패키지와 실행 시 JSON 검사를 대신하지 않는다.
- [3심 수정 계약 실험](evidence/2026-10-14/review-3-revised-contract-results.json): 실제 Yjs API를 제안 메서드 경계로 연결한 7개 사례와 별도 과정 반복이다. 정상 no-op/거절, 잘못된 수락, 순서쌍 누락, 새 명령·분할, 중단·빈 복구 메시지를 구분했다. 제품 실행기·기록 메시지 재생·JCS·전체 자원의 합격은 아니다.
- [기존 회귀 결과](evidence/2026-10-14/baseline-results.json): 변경하지 않은 제품의 lint/typecheck/build/test/test:deep 결과다. 기존 결함이 수정됐거나 목표 기능이 구현됐다는 증거가 아니다.
- [실험 원문](evidence/2026-10-14/proofs.md)과 의존성 고정 파일, 결과·검토 자료의 SHA-256은 최종 manifest.json에 보관한다.

현재 성능 측정은 901 사건이다. 10,000 사건·최대 입력·전체 메모리·다른 저장소의 실제 사용은 G5에서 측정한다. 기존 브라우저 자료는 현재 제품 반례를 확인한 결과이며 새 화면의 합격이 아니다.

## 설계 수락 조건

1·2심의 모든 중요 지적이 수정 후 실제 대조로 종료하고, 3심이 같은 최종 파일 해시를 대상으로 이를 확인해야 한다. 열린 중요 지적·미확인 주장·정본 충돌이 있으면 수락하지 않는다. 최종 자료 검증과 기존 코드 보존도 명령 결과로 확인한다.

수락은 구현을 진행할 수 있는 설계 판단이다. 제품 G0–G5, 업계 제품과의 우위 비교, 모든 결함의 부재, 보편적 신뢰성은 수락 범위에 포함하지 않는다. [PROJECT 확정 기준, RESEARCH S03]

실행 기록의 재생을 실제 대상 검증으로 확대하되 외부 대상의 전제를 계약에 고정하고, 업무 규칙·파일 공유·자동 검사 종료를 주기능으로 선택했다. 파일이 기본이고 SQLite는 표 3개와 조회 색인 1개만 사용한다. 새 운영 서비스와 계정·조직·과금 기능은 없다. 이는 목적과 실패 반례에 따른 설계 수락이며 외부 제품 대비 우위의 입증은 아니다. [DESIGN §2–8, RESEARCH S01–S20]

G0의 현재 결함 수정과 공통 경계 정비를 먼저 구현한다. 각 단계의 필수 합격이 완료돼야 다음 단계의 완료를 주장한다. 목표 CLI·웹·저장 연결과 다른 저장소의 실제 사용은 현재 구현되지 않았다. [DESIGN §9–10]
